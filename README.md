# 배드민턴 코트보드

배드민턴 모임에서 쓰는 실시간 운영 보드입니다. 링크를 받은 사람은 누구나 들어올 수 있고, 한 사람이 바꾼 내용이 접속한 모든 사람의 화면에 바로 반영됩니다.

| 버전 | 주소 | 파일 |
| --- | --- | --- |
| 1버전 (팀짜기 보드) | https://remaster201906-netizen.github.io/badminton-courtboard/ | `index.html` |
| 2버전 (출석~시상식) | https://remaster201906-netizen.github.io/badminton-courtboard/v2/ | `v2/index.html` |

## 2버전 구성 (사이트맵)

`v2/index.html` 한 파일 안에 탭으로 나뉘어 있습니다.

1. **출석**: 참석 투표 링크 복사, 실시간 출석 체크, 게스트 추가/제외, 급수(A·B·C·D·초심)·성별, 프로필 캐릭터 선택, 출석 시 내 통산 승률 표시
2. **설정**: 코트 수와 번호, 매칭 옵션(레벨 밸런스 우선 / 휴식 형평성 우선, 겹침 최소화, 성비, 대기 게임 자동 개수)
3. **코트**: 스마트 자동 매칭, 코트 현황판, 대기 게임, 이름을 눌러 수동 변경
4. **전광판**: 내 다음 순서, 진행 중 경기, 대기열 (모바일 공유용 링크 `#live-모임번호`)
5. **기록·랭킹**: 스코어 입력·수정, 개인별 게임 수·승률·득실차·총 대기 시간
6. **마감·시상**: 모임 종료, 종합 순위 정산, 1~3등 포디움, 시상 이미지 저장

주소 형식: `…/v2/#m-1234`(운영), `…/v2/#vote-1234`(참석 투표), `…/v2/#live-1234`(전광판)

### 자동 매칭 방식

대기 순서(게임 수 적은 사람 → 오래 기다린 사람) 맨 앞 사람은 반드시 다음 게임에 넣습니다. 나머지 3명과 팀 나누기는 아래 감점의 합이 가장 작은 조합으로 고릅니다. (`v2/index.html`의 `pickFour`)

- 대기 순서에서 뒤쪽 사람을 끌어올수록 감점
- 4명의 급수 차이, 양 팀 급수 합 차이
- 오늘 이미 같은 파트너였던 횟수 ×3, 상대였던 횟수 ×1
- 남녀 3:1 조합, 남남 vs 여여 조합

"휴식 형평성 우선"은 대기 순서 감점을 크게, "레벨 밸런스 우선"은 급수 감점을 크게 줍니다.

### 데이터 구조 (Firestore)

```
meets/{모임번호}                이름, 날짜, 코트 번호 목록, 매칭 옵션, 상태
  players/{id}                 닉네임, 성별, 급수, 캐릭터, 투표, 출석, 휴식, 퇴장
  courts/c{번호}               slots[4] (A팀 2명, B팀 2명), 시작 시각
  queue/{id}                   대기 게임 slots[4], 순서
  matches/{id}                 코트, a[2], b[2], 점수, 시작·종료 시각
profiles/{닉네임}               통산 경기·승·패·득실 (모임 마감 때 더해짐)
rooms/…                        1버전 데이터
```

게임 수, 승패, 순위, 대기 시간은 저장하지 않고 `matches`에서 매번 계산합니다. 그래서 스코어를 고치거나 지우면 순위가 바로 다시 계산됩니다.

## 파일

| 파일 | 설명 |
| --- | --- |
| `index.html` | 1버전 |
| `v2/index.html` | 2버전 |
| `firebase-config.js` | Firebase 웹 앱 설정 (두 버전이 같이 씀) |

| `firebase.json`, `.firebaserc` | 보안 규칙 배포 설정 |

빌드 과정은 없습니다. 파일을 고치고 GitHub에 올리면 1~2분 안에 사이트가 바뀝니다.

## 알아둘 점

- 로그인 없는 공개 보드입니다. 링크나 번호를 아는 사람은 누구나 명단과 결과를 바꿀 수 있어요. 모임 안에서만 공유하세요.
- 통산 기록은 닉네임 기준입니다. 같은 사람은 매번 같은 닉네임을 써야 이어집니다.
- Firestore 무료 한도(하루 읽기 5만 / 쓰기 2만 회)는 30~40명 모임이 매일 써도 넉넉합니다.
